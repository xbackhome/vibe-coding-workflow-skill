# 单一来源与多 Agent 分发

## 唯一维护源

这份 Skill 的维护源是维护者指定的项目仓库中包含 `SKILL.md` 与 `references/` 的完整目录。分发记录应写明该次实际源路径和版本。其他 Agent 的 Skill 目录只接收已确认版本，修改先回到源仓库，不能让多个副本各自演化。

Agent 的安装目录可能是独立副本，不能假设源文件修改会自动同步。安装位置因工具和机器而异，分发前实际检查目标路径，不把某个通用路径当成所有 Agent 的默认值。

Skill 保存可复用的开发方法。具体项目的规格、计划、验收表和测试证据保存在该项目的既有文档位置。多个 Agent 开发同一项目时，应引用同一规格路径和版本，分别处理划定的任务与文件范围，避免复制出多份需求或同时修改同一文件。

## 保留旧版本

用户要求保留原版本时，在修改前将完整 Skill 包复制到源仓库之外的留存目录，包含所有引用资源及已保存的未提交内容；逐文件保存清单与 SHA-256 校验值，核对复制结果。Git 旧提交不能代替尚未提交内容的备份。备份元数据、变更说明和验证记录保存在 Skill 包之外。

留存副本用于追溯和回滚，继续编辑当前维护源。分发或启用时明确选择源版本，避免把留存副本混入安装目录。需要恢复时先保存当前工作，再核对要恢复的包、版本和清单，按授权执行。

## 获准分发时的步骤

1. 确认源版本和目标 Agent／目录，以及安装、更新或发布是否已得到用户授权。修改源文件不自动触发安装或外部发布。
2. 验证 Skill 元数据、引用文件和行为规则。在将要安装或启用的环境中，按适用的用户与项目规则对实际待安装的完整 Skill 包进行安全扫描；不满足当地规则时停止安装或启用并说明原因。源仓库此前的扫描结果不能代替目标环境对实际包的检查。
3. 检查目标副本是否有本地修改；有差异先保存并核对，不能静默覆盖。使用目标环境支持的链接或复制机制：能可靠引用同一目录时可以使用链接，否则分发完整副本。不要预设所有 Agent 都支持符号链接。
4. 分发完整 Skill 包及它引用的文件，排除 .git、凭据和项目运行数据。复制模式要依据源文件清单处理旧文件，避免新旧版本混用；删除目标文件仍须遵守授权与保留本地改动的要求。
5. 在源仓库之外记录分发结果：目标位置、源版本、文件清单与校验值、扫描结果、时间。未提交的草稿使用明确草稿标识与文件校验值，不能借用旧 commit 冒充新版本。
6. 确认目标文件与获准版本一致，并按该 Agent 的实际机制刷新发现状态。文件复制成功不等于已经加载生效；区分已同步、已发现和已验证调用。

回滚时使用同一机制分发已确认的旧版本。来源或目标尚未明确时，先完成源文件修改与校验，报告分发待定，不自动安装或发布。

以上规定版本留存与分发操作；定时同步、注册和跨 Agent 自动分发需要单独实现并验证，不能仅凭规则文件声称已有自动化能力。

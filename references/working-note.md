# Working note template

Use this only when decisions must survive multiple sessions or when the feature has several interacting rules. Keep it concise and update it as decisions change.

```markdown
# <Feature or product>

## Outcome
User, problem, core journey, and observable success.

## Constraints
Platform, deployment, data, integrations, budget, and applicable project rules.

## Terms and decisions
Definitions that could otherwise be interpreted differently; confirmed decisions with reasons.

## First slice
In scope, out of scope, business rules, material error cases, and acceptance examples.

## Existing work
Closest open-source precedent and adopt/adapt/reference/build decision, if this is a new product or major design choice. Existing repository code to reuse.

## Implementation
Next small runnable step, expected files or modules, and verification method.

## Progress and evidence
Completed slices, commands or interactions actually checked, outcomes, and remaining gaps.

## Open decisions
Only items that can change implementation or acceptance.
```

# 开源项目匹配与流程交接

在新想法、项目调研或审核、规划、架构设计、技术与依赖选择、实施路径决策之前使用。先从用户描述和已有项目文件整理目标用户、期望结果、核心流程、交付形式及部署、数据、预算、硬件等关键约束。只澄清会改变候选清单的缺口；想法尚不足以检索时，先补足基本目标，不编造推荐。

## 执行入口

当前 Agent 已有 `project-open-source-scout` 时，读取并执行该 Skill 的当前版本；`vibe-coding-workflow` 负责把结果交给后续阶段，不复制或修改另一份 Skill。它尚未安装或当前 Agent 无法调用时，不为此自动安装：依照下方最低要求自行调研，明确说明未调用外部 Skill 及实际完成的范围。用户明确要求跳过开源匹配时记录原因并继续授权范围内的工作。范围清楚的局部维护、无新的方案选择的 Bug 修复，可直接沿用已有项目决策；新证据改变选择时重新匹配。

## 最低调研要求

1. 检索当前上游：通用软件先查 GitHub；模型和数据项目按需查 Hugging Face、ModelScope；中国生态按需查 Gitee；目录和榜单仅用于发现候选，结论回到原仓库核查。记录实际查过的范围和时间。
2. 只保留有可访问上游、明确功能匹配、已核实许可证、维护证据或可解释的旧版使用理由、且符合关键约束的项目。未知许可证、维护失活而无法解释、部署或数据边界冲突的候选应排除或标为待核查，不因名称相似纳入清单。
3. 对入围项目按功能匹配 35、部署与数据适配 15、可复用内容 15、维护情况 15、许可证 10、文档与社区 10 分评估；分数是比较工具，不代替证据。给出简短中文高匹配清单，逐项附上游链接、实际可用部分、可借鉴的方法、最短使用路径、限制与采用建议。找不到合格候选时如实说明搜索边界，不凑数。
4. 建议直接采用、仅参考、学习方法或不使用，并解释自行开发是否有依据。推荐路径与重要取舍尚未由用户决定时，先交付清单与建议，等待决定后再推进受影响的实施；已有明确选择不重复询问。只调研不等于获得安装、复制代码或更改技术方案的授权；采用前再核对具体版本、许可证和适用的安全规则。

## 检索充分性门槛

`project-open-source-scout` 的清单也要经过本门槛复核，不能把调用了 Skill 或列出几个项目当成调研充分的证据。完成推荐前：

1. 从核心流程、必须具备的能力和关键部署约束拆出检索主题；使用中英文关键词、常见别名和相邻技术路线。除直接搜仓库名称外，按功能、生态分类或上游项目的相关链接扩展候选，并记录实际使用的检索路径。不同类别可落在同一平台，不机械要求访问无关网站。
2. 对初轮最相关的候选再查一次：沿其功能术语、依赖、竞品或替代方案追溯上游，针对最可能遗漏的项目补充检索。核对主要解决路径是否都有代表性候选；新发现更匹配的项目时继续比较，而不是因已有清单就停止。
3. 对最终候选逐项核对上游的实际能力、许可证、维护状态和关键约束；说明为什么入围，以及被排除的高相关项目缺少什么。候选数量和搜索次数不是完成标准，判断重点是现有证据能否支撑当前采用或自建建议。

交付时简要写明检索主题、来源、扩展检索发现了什么、仍可能遗漏的范围。仍有明显缺口且能够继续检索时，先补查；只有上游访问受阻、关键约束待定或用户明确限定调研范围时，才交付**初步清单**并列出待补查项。不能把“本轮没有搜到”写成“没有同类项目”，也不能据此断言必须自建。检索充分只针对当前决策与已知约束，不承诺穷尽整个开源生态。

## 用户选择自建时

以自有项目为主体，逐项区分可直接复用的代码、可借鉴的技术或设计方案，以及需要自行实现的缺口。对拟复用部分核对许可证、版本兼容性、部署与数据约束和长期维护成本；适配且获准使用的成熟能力优先复用，不为形式上的“自建”重复实现。只借鉴思路时说明具体借鉴点，不把未经核查的外部代码直接复制进项目。把最终取舍及理由交给规格与实施计划。

## 交接到 Vibe Coding 工作流

- **头脑风暴**：把候选项目当作现有替代做法，讨论真实差异、可复用能力、缺失场景与成本，不把竞品存在等同于项目无意义。
- **合理性审查**：用候选项目与用户目标比较价值和可行性；把来源证据、推断和待实验问题分开。已有项目还要核对当前实现与拟议方案的差距。
- **规格与计划**：只把用户已确认的采用范围、约束和验收结果写入规格；具体技术选择及理由放在计划或架构决策记录。未确认的候选保留待决，不伪装成需求。
- **跨会话记录**：在[工作记录](working-note.md)中保存检索日期、来源、入围与排除理由、选择及其确认状态。后续决策若依赖容易变化的维护或许可证信息，先重新核对。

联网或上游访问不可用时，列出未核实的项目与缺失证据，不声称完成了当前开源匹配；可以继续已授权且不依赖该选择的工作。

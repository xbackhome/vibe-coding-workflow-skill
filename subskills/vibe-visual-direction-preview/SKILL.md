# 三方向视觉预览

让不懂设计术语的用户先看到选择，再用“喜欢哪里、不喜欢哪里”确认方向。本子 Skill 由 `vibe-coding-workflow` 在视觉方向不明时读取；它是父 Skill 包内的流程文件，未单独安装时不能假定可用 `$vibe-visual-direction-preview` 直接调用。

## 先确定比较基线

读取项目用途、目标用户、现有页面与内容、已确认的功能和设计约束。挑选能代表本次决策的页面或流程；三个方向使用相同的页面范围、中文文案、样例数据、可见功能与状态。已有品牌或设计系统中的硬约束要保留。只问会改变方向选择的缺口，不要求用户先说出“高级、克制、现代”等设计术语。

## 先看三个方向

制作**三个明显不同**的方向。布局与信息层级、配色和字体应形成可辨认的组合差异，不能只换三套颜色。以隔离的 HTML 页面、可操作原型或渲染图片交付同等完成度的预览；仅有文字描述、代码片段或设计提示词不算预览。静态预览可以用于选择视觉方向，但须标明未实现的交互；三个方案的功能范围必须一致。

实际打开或展示三个预览，让用户并排或逐个比较。每个方向用通俗语言说明适合的用户与场景、最明显的优点、主要取舍和与现有界面的关系。预览阶段不把三个方案都写进正式产品。若当前环境无法渲染或展示，说明缺少的能力和可执行的预览方式，保留“未展示”状态，不用文字清单冒充已交付预览。

## 选定一个再实施

请用户指出喜欢和不喜欢的具体位置，记录被选方向及必要修改；已有明确选择则沿用，不重复索要确认。选择前不把某个方向整合到正式项目。选定后只实施该方向，沿用既有内容和功能要求，在项目原有设计文档中记录配色、字体及中文回退、间距、组件样式和关键状态规则；没有合适文档时建立简短的设计规则文件，并在工作记录中引用。

完成后在真实页面检查桌面和手机布局、中文字体与回退、长文本、空状态、错误状态；按项目需要补查对比度、焦点和主要交互。打开页面展示实现结果，记录实际查看的环境、发现和修正。截图或静态预览不能代替对真实交互的验证；无法打开目标页面时标明未验证并给出用户可执行的查看步骤。

## 工具选择与边界

若当前 Agent 已可用 [Impeccable](https://github.com/pbakaus/impeccable)，优先用其适合当前版本的设计与浏览器迭代能力辅助工作；三方向、同内容比较和选后实施仍由本 Skill 约束。未安装时沿用当前 Agent 的设计、代码和预览能力，不为完成任务自动安装 Impeccable 或叠加整套设计工具。任何第三方 Skill 或插件安装、启用前，先对实际目标执行 `skillspector scan <目标> --no-llm`；仅评分不高于 50 且符合当前授权时继续，扫描失败则停止。

## 给编程 Agent 的启动语

> 我不懂设计术语，也说不清想要什么。请根据项目用途和现有内容，先用相同的页面、文案、数据和功能范围做三个明显不同、能打开看的视觉预览，让我比较布局、配色和字体。说明每个方向适合谁、主要取舍是什么。等我选定后，只实现选中的方向并记录统一设计规则。完成后打开真实页面，检查桌面和手机、中文字体、长文本、空状态及错误状态，并展示结果。
